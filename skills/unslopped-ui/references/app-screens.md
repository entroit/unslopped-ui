# Operational screens

Read this for dashboards, tables, charts and working app screens. Start with the decision the user must make. Keep the information and controls that help that decision; choose their arrangement before their decoration.

## Hierarchy and density

Give the current scope, time period and main action clear positions. Group related facts by proximity and alignment. Reserve containers for distinct objects, actions or states. Compare a compact row, a divided section and a card before adding a card around every value.

Use consistent labels, units and alignment across comparable values. Right-align numeric columns and use tabular numerals where digit alignment matters. A numeric font can remain the product's existing face. Increase the value's prominence only when the task gives it priority. Avoid making every KPI, status, icon and action equally prominent.

An empty area can preserve a useful reading path or leave room for a task. Remove accidental gaps caused by stretched cards, mismatched columns or inappropriate marketing spacing. Use actual content lengths, including long names and translated labels.

## Data meaning

Identify the source, population, denominator, period and freshness of each summary. Derive related KPIs and charts from the same data and definitions. Calculate at source precision, then format for display. Explain rounding differences rather than changing totals to force rounded parts to add up.

Show unavailable, zero, loading and failed data as different states. A static example is demo data or a snapshot. A live label needs an actual update mechanism. Comparative percentages need a valid comparison period; a newly created account cannot have invented prior growth.

Choose the mark for the comparison:

- Bars encode magnitude through length and normally need a zero baseline. If the useful range is narrow, a dot plot or line with a clearly labeled scale can show the variation without implying a length comparison.
- Lines show ordered change. Show actual timestamps and distinguish gaps from zero. Smoothing must not invent peaks or crossings.
- A donut can show a simple part-to-whole relationship. Prefer a bar or direct values when precise comparisons, many parts or similar sizes matter.
- Sparklines need a useful trend, a known period and enough context. An ornamental line beside every number adds no evidence.

Keep units, significant baselines and comparison periods available. Use shared scales for panels meant to be compared. Label important marks directly when that reduces lookup. Provide values beyond hover through visible text, an accessible table or an equivalent control.

## Actions and status

Use status color consistently and pair it with text, shape or position. Negative change is not automatically bad. Select a label and action that reflect the actual domain.

Keep sorting, filtering, selection and pagination connected to real behavior. Show the current filter scope and offer a clear reset when it can explain an empty result. Preserve row actions on touch and keyboard, even when they appear on pointer hover on wider screens.
