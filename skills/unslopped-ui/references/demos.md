# UI demonstrations and videos

Read this when creating a before-and-after recording, comparison or UI explainer. The video should demonstrate the design decisions that the skill recommends.

Keep the comparison about observable problems and their repairs. A caption such as "Give the delay a clear priority" names a task improvement. A blanket claim that a font, hue or chart type is bad overstates the evidence. Demonstrate why a particular choice fails in this example.

Use the same underlying content and definitions across the comparison unless correcting them is an explicit lesson. Derive related numbers from a shared dataset. Label invented data as demo data or a snapshot, and keep that disclosure legible. Use a live label only when the demonstration actually represents live updates.

Preserve the meaning of chart marks. Bars normally start at zero; use a position-based mark and a labeled scale for a narrow range. Keep visible values consistent with the plotted geometry. A chart correction should remain correct during transitions as well as in the ending frame.

Make the lesson readable at the size viewers will see in the feed. Give each change enough time to recognize, and test downscaled output. Keep text clear through camera motion and comparison wipes. Show the completed result long enough to inspect it. Avoid ending on a transient or partially revealed state.

A rendered video can depict an interface without implementing every pictured control. Present it as a demonstration. Do not describe those depicted controls as verified working functionality. If the accompanying app is part of the deliverable, verify that app separately.

Render representative frames before the full encode. Inspect the actual finished video at the opening, each lesson, transitions and final hold. Check duration, dimensions, frame rate, codec and any audio. Sample the encoded frames too; correct HTML is not proof of a correct export.

Use a fresh version when revising a delivered video, and keep the previous version available. Report the substantive differences. A checklist count or "zero tells" badge must not imply that the work passed an exhaustive quality or accessibility audit.
