# Unslopped UI

Make the interface fit its product, content and users. Fix the specific problem the brief identifies.

## Work from the actual product

Inspect the target, its code and existing design tokens. Identify the user's main task, the content it needs, and the behavior that must survive. Distinguish a review, a scoped refinement and an authorized redesign. For a review, report findings without making unrequested changes. For an edit, proceed with the available evidence; ask only when missing information changes the outcome materially.

Apply requirements in this order: truthful content and required accessibility, the user's brief, the existing product system, the selected recipe, then general defaults. A font, hue, rounded card, gradient or conventional layout is not a defect by itself. Find the actual problem in reading, comparison, navigation, action or identity.

## Make and verify the change

For each meaningful finding, identify the element or state, the observed problem, its effect on the task, and the smallest coherent repair. Preserve routes, useful content, data meaning and working behavior. When a new identity is requested, decide its type, palette, composition and interaction together before extending it across the page.

Implement the authorized changes. Check the actual rendered result and the affected interactions. Report what changed, the evidence checked and any remaining limitation. A passing scanner, a build or a screenshot supports only what it actually tested. Keep a deliberate style when it fits the brief and works.
